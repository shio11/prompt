# `main_vertical.py` ソースコード解説書

## 1. 概要

`main_vertical.py` は、Excelの「**縦レイアウト（項目名が行方向に並ぶ）**」テンプレートに対応した、Tkinter製のデスクトップGUIアプリケーションです。

元になった `main.py`（横レイアウト・単一レコード版）から発展させたもので、次の特徴があります。

1. **縦レイアウト対応**：A列に項目名、B列以降に値が並ぶ形式のExcelを読み書きする
2. **複数レコード対応**：1つのファイルに複数人分のデータが列として並んでいても、まとめて読み込める（列数は可変）
3. **項目名セルの位置を問わない**：項目名が必ずしもA列・1行目から始まっていなくても（例：D列3行目からでも）検索して見つけ出す
4. **横レイアウトへの後方互換**：従来の「1行目=見出し、2行目=データ」形式のファイルも、フォールバックとして引き続き読み込める
5. **GUIでのレコード切り替え**：「前へ／次へ」ボタンで複数レコードを1件ずつ表示・編集できる

対象とする項目（`FIELDS`）は元のバージョンと同じ8項目です（氏名／フリガナ／会社名／部署／メールアドレス／電話番号／日付／備考）。

## 3. 全体構成

```
main_vertical.py
├── FIELDS                    … フォーム項目名の一覧（定数）
├── TEMPLATE_PATH              … template_vertical.xlsx への絶対パス（定数）
├── ITEM_HEADER / VALUE_HEADER_PREFIX … 見出し文字列（"項目" / "値"）
├── Record                     … dict[str, str] の型エイリアス（1レコード分）
├── ensure_template()          … テンプレートが無ければ縦レイアウトで新規作成
├── load_template_records()    … テンプレートを複数レコードとして読み込む
├── read_external_file()       … 外部Excelファイルを複数レコードとして読み込む
├── write_output_file()        … 複数レコードを縦レイアウトExcelとして書き出す
├── _is_usable_value()         … セルの値が「データ」として使えるかを判定
├── _read_labeled_records()    … 上記3関数が共通で使う中核の読み込みロジック
├── TemplateApp                … GUI本体のクラス（複数レコード・前後移動対応）
└── main()                     … エントリーポイント
```

処理の全体像は次の通りです。

```
[起動]
  │
  ▼
ensure_template()  ── template_vertical.xlsx が無ければ縦レイアウトの雛形を新規作成
  │
  ▼
TemplateApp 生成 → _load_initial_values() → load_template_records()
  │                                              │
  ▼                                              ▼
フォーム画面表示                       複数レコードのリストを取得し
（1件目を表示、位置表示"1 / N"）        self._records に保持
  │
  ├─ 「前へ／次へ」ボタン
  │      → 編集中の内容を保存 → インデックス移動 → フォーム再表示
  │
  ├─ 「＋ 新規レコード追加」ボタン
  │      → 空レコードを末尾に追加 → そこへ移動
  │
  ├─ 「外部ファイルを読み込む」ボタン
  │      → read_external_file() → self._records を丸ごと差し替え
  │
  └─ 「出力する」ボタン
         → 編集中の内容を保存 → write_output_file() → 全レコードをExcelとして保存
```

## 4. 定数・型

### `FIELDS: list[str]`
対象とする8項目のリスト。並び順が、出力Excelの行の並び順（A列の項目名の順序）になります。

### `TEMPLATE_PATH: Path`
`main_vertical.py` と同じフォルダの `template_vertical.xlsx` を指すパスです。

### `ITEM_HEADER`, `VALUE_HEADER_PREFIX`
新規テンプレート作成・出力時に使う見出し文字列です。`VALUE_HEADER_PREFIX` は `"値"` で、レコードごとに `値1`, `値2`, ... という見出しを自動生成するために使われます。

### `Record = dict[str, str]`
「1人分のデータ」を表す型エイリアスです。`{"氏名": "山田太郎", "会社名": "〇〇株式会社", ...}` のような辞書を指します。アプリ全体でこの `Record` の**リスト**（`list[Record]`）を扱うことで、複数レコードに対応しています。

## 5. 関数の解説

### `ensure_template(path: Path) -> None`
テンプレートファイルが存在しない場合、以下の内容で新規作成します。

- `A1` = `"項目"`、`B1` = `"値1"`（見出し行、グレー背景・太字・罫線付き）
- `A2〜A9` = `FIELDS` の各項目名、`B2〜B9` は空欄

初回起動時にファイルが無くてもエラーにならないための安全策で、最初は1レコード分（B列のみ）の空テンプレートとして作られます。

### `load_template_records(path: Path) -> list[Record]`
テンプレートファイルを読み込み、`_read_labeled_records()` の結果（複数レコードのリスト）をそのまま返します。アプリ起動時にフォームへ初期値を反映するために使われます。

### `read_external_file(path: Path) -> list[Record]`
ユーザーが選択した任意のExcelファイルを読み込みます。中身は `load_template_records` と同じ `_read_labeled_records()` を呼ぶだけですが、**縦レイアウトで何も見つからなかった場合は横レイアウト（従来形式）にフォールバックする**点が重要です（詳細は後述）。

### `write_output_file(path: Path, records: list[Record]) -> None`
複数レコードを新しいExcelファイルとして書き出します。

- `A1` = `"項目"`、`B1, C1, ...` = `値1, 値2, ...`（レコード数分の見出しを自動生成）
- `A2〜A9` = `FIELDS`
- `B列以降の各行` = 各レコードの、その項目に対応する値（`record.get(field, "")` により未入力項目は空文字で出力）
- レコードが1件も無い場合（空リスト）は、空のレコード1件として扱い、最低限のヘッダーだけは出力される

### `_is_usable_value(raw_value: object) -> bool`
セルの値を「データとして採用してよいか」判定する小さなヘルパー関数です。

- `None`（空セル）や空文字列は不採用
- 値が偶然 `FIELDS` の項目名と一致する場合（＝別の見出しセルを誤って値として読んでしまうケース）も不採用

この判定があることで、後述の `_read_labeled_records` が「見出しセル同士が隣接している」状況（例：横レイアウトの見出し行）を値として誤読しないようになっています。

### `_read_labeled_records(sheet: Worksheet) -> list[Record]` ── 中核ロジック

この関数がアプリの心臓部です。2段階の探索を行います。

**① 縦レイアウト・複数列としての探索（優先）**

1. シートの各行を1行ずつ確認
2. その行を左から順に見て、`FIELDS` のいずれかと一致し、かつまだ見つかっていない項目名のセルを探す（**何列目にあっても構わない** — 例えばA列でもD列でも検出可能）
3. 見つかった項目名セルより右側の全セルを、「レコード1, レコード2, ...」の値として順番に取得（末尾の空セルだけ切り詰め、途中の空セルは `""` として保持し、列位置のズレを防ぐ）
4. 全行を確認し終えたら、`{項目名: [値1, 値2, ...]}` の形にまとめる
5. 最も列数が多かった項目のレコード数を `max_len` とし、各レコードごとに `{項目名: その位置の値}` の辞書を組み立てて `list[Record]` として返す

この方式のため、項目名がA列以外（例：D列）から始まっていても、行の途中に空行や無関係なメモが混ざっていても、項目名セルさえ見つかれば正しく読み取れます。

**② 横レイアウト・単一レコードへのフォールバック**

①の結果、`FIELDS` に一致する項目が1つも見つからない、またはすべて空だった場合（`has_any_value` が `False`）、従来の `main.py` と同じロジックにフォールバックします。

- 1行目をヘッダー行とみなし、列名が `FIELDS` と一致する列を特定
- 2行目のみをデータ行として読み取り、1件のレコードとして返す

これにより、以前の横レイアウトテンプレート（`template.xlsx`）も引き続き問題なく読み込めます。

## 6. `TemplateApp` クラス（GUI本体）

### `__init__(self, root: tk.Tk)`
`self._records`（`list[Record]`、初期値は空レコード1件）と `self._current_index`（現在表示中のレコード番号、0始まり）を保持します。ウィジェット構築後、テンプレートから初期レコードを読み込みます。

### `_build_widgets(self)`
画面レイアウトを構築します。元のバージョンからの変更点は次のナビゲーション部分です。

- **「◀ 前へ」「次へ ▶」ボタン**：`_on_prev` / `_on_next` を呼ぶ
- **位置表示ラベル**（`self._position_label`）：`"2 / 5"` のように現在位置／総数を表示
- **「＋ 新規レコード追加」ボタン**：`_on_add_record` を呼ぶ

### `_load_initial_values(self)`
`load_template_records()` で複数レコードを取得し、`self._records` にセットしたうえで `_refresh_form()` を呼びます。失敗時はエラーダイアログを表示します。

### `_refresh_form(self)`
現在の `self._current_index` に対応するレコードをフォームに表示し、位置表示ラベルを更新します。レコードが0件になってしまった場合は空レコード1件を補い、インデックスが範囲外にならないよう調整（クランプ）します。

### `_set_values` / `_get_values`
フォームとレコード（辞書）の間で値をやり取りする共通処理です（元のバージョンと同じ役割）。

### `_save_current_entry_to_records(self)`
**フォームに今入力されている内容を、現在表示中のレコードに書き戻す**処理です。「前へ／次へ」で移動する前や、出力する直前に必ず呼ばれるため、編集中の内容がレコード切り替えで消えることはありません。

### `_on_prev(self)` / `_on_next(self)`
現在の編集内容を保存してから、インデックスを1つ前／後ろに移動し、フォームを再表示します。先頭・末尾では何もしません。

### `_on_add_record(self)`
現在の編集内容を保存したうえで、空のレコード（`{}`）を末尾に追加し、そこへ移動します。複数列テンプレートに新しい人を追加したい場合に使います。

### `_on_import(self)`（「外部ファイルを読み込む」ボタンの処理）
1. ファイル選択ダイアログを表示
2. `read_external_file()` で複数レコードを取得
3. 1件も有効な値が無ければ警告ダイアログを表示して終了
4. 成功すれば `self._records` を丸ごと差し替え、1件目からフォームに表示
5. 完了メッセージに読み込んだレコード数を表示

### `_on_export(self)`（「出力する」ボタンの処理）
1. 保存先ファイルを選択するダイアログを表示
2. 編集中の内容を `self._records` に保存
3. `write_output_file()` で **全レコード**を書き出す
4. 完了メッセージに出力したレコード数を表示

## 7. `main()` — エントリーポイント

```python
def main() -> None:
    ensure_template(TEMPLATE_PATH)
    root = tk.Tk()
    TemplateApp(root)
    root.mainloop()
```

処理の流れは元のバージョンと同じです。`template_vertical.xlsx` が無ければ新規作成し、GUIを起動してイベントループへ入ります。

## 8. 元の `main.py` との主な違い（比較表）

| 項目 | `main.py`（横レイアウト・単一レコード） | `main_vertical.py`（縦レイアウト・複数レコード） |
|---|---|---|
| データ構造 | `dict[str, str]`（1件のみ） | `list[dict[str, str]]`（複数件） |
| レイアウト前提 | 1行目=見出し、2行目=データ | A列以降=項目名、B列以降=値（列数可変） |
| 項目名の位置 | 1行目固定 | 行内のどの列でも検出可能 |
| 読み込み対象 | 2行目のみ | 全行を走査、複数列にも対応 |
| GUI | フォーム1件のみ | フォーム＋前へ／次へ／新規追加 |
| 後方互換 | ― | 縦レイアウトで見つからなければ旧形式にフォールバック |

## 9. エラーハンドリングの方針

読み込み・出力の各処理は `try/except Exception` で囲まれ、失敗時は `messagebox.showerror` でエラー内容を表示します。想定外の例外でもアプリ自体はクラッシュせず、原因メッセージがそのままダイアログに表示される設計は元のバージョンを踏襲しています。

## 10. まとめ

このバージョンの核心は `_read_labeled_records()` にあります。「項目名セルを行内のどこからでも探し、その右側を可変長のレコード列として読む」という単純なルールにすることで、A列開始・D列開始・列数の増減・従来の横レイアウトまで、幅広いExcelの形式を1つのロジックで吸収しています。GUI側は「今どのレコードを編集しているか」を `self._current_index` で管理し、切り替えの都度フォーム内容をレコードへ保存することで、複数人分のデータをスムーズに行き来しながら編集できるようになっています。
